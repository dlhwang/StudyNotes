### 3.2 Aegra

Agent를 Aegra 서버에 올린다. 대화 상태(체크포인트)를 PostgreSQL에 둔다.

1. PostgreSQL을 띄운다(이 PC: 서비스 `postgresql-x64-17`). DB `aegra`를 만든다.
2. `.env.example`을 `.env`로 복사하고 채운다.

| 키 | 값 |
|---|---|
| `POSTGRES_HOST/PORT/DB/USER/PASSWORD` | 위 DB. `DATABASE_URL`은 두지 않는다(있으면 Aegra가 먼저 쓴다) |
| `STUDY_NOTES_BE__MODE` | `http` (Aegra 안의 Agent가 BE를 HTTP로 부른다) |
| `STUDY_NOTES_BE__BASE_URL` | `http://127.0.0.1:8000` |
| `NOTES_API_AGENT_MODE` | `aegra` |

3. 서버 묶음을 넣고 접속을 확인한다.

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[server,postgres]"
```

```powershell
.\.venv\Scripts\python.exe -m study_notes.db check
```

4. 띄운다. Aegra는 처음 뜰 때 자기 테이블을 만든다.

```powershell
.\tools\run_dev.ps1 -Aegra
```

5. Aegra에 BE처럼 붙어 본다(노트 질문, 메모리, daily_review).

```powershell
.\.venv\Scripts\python.exe tools\smoke_aegra.py
```

Aegra API 문서는 `http://127.0.0.1:2026/docs`.

## 4. 기능 하나 넣기

예: notes Agent에 "최근에 쓴 노트 보여줘"(`note_recent`)를 넣는다.

### 4.1 의도

`agents/notes/agent.py`의 `intents`에 `IntentSpec`을 추가한다. 오케스트레이터는 고치지 않는다.

```python
NOTE_RECENT = IntentSpec("note_recent", "최근 노트 보기", (r"최근.*(노트|메모)",))

class NotesAgent(BaseAgent):
    intents = (NOTE_SUMMARY, NOTE_RECENT, NOTE_SEARCH, NOTE_QA)  # 앞에 둔 것부터 규칙을 건다
```

- 규칙은 공백을 지우고 소문자로 바꾼 질문에 건다. 다른 의도와 겹치면 부정 전방탐색(`^(?!.*(요약)).*`)으로 좁힌다. 겹침 시험: `tests/unit/test_review_rules.py::test_review_intents_do_not_collide`.
- 규칙에 안 걸리면 모델(`router`, 프롬프트 `orchestrator.classify.v2.md`)이 고른다. few-shot 예시에 새 의도를 하나 넣는다.

### 4.2 도구 (조회)

`agents/notes/tools.py`. 이름 `notes_<동사>_<대상>`, 첫 인자 Pydantic 모델, 독스트링에 언제 쓰고 언제 쓰지 않는지.

- 모델이 ReAct에서 고르게 하려면 `@agent_tool(agent="notes", llm_selectable=True)`.
- BE에 새 조회가 필요하면: BE 내부 API(`notes_api/routes/internal.py`, GET) → `BeClient`(`tools/be_client/protocol.py`) → `http.py` → `tools/fakes/be.py` → 계약 시험(`tests/contract`).

### 4.3 답 만들기

- 숫자는 BE가 계산한 것만 쓴다.
- 모델: `ask_llm`(문장), `ask_llm_json(Model, ...)`(구조화 출력), `react(...)`(도구를 고르며 답). 모두 실패하면 `LlmUnavailableError` → 규칙 답. 가짜 모델은 늘 실패하므로 **규칙 답만으로 기능이 돌아야 한다.**
- 다룬 노트는 `data={"focus_note_ids": [...]}`에 넣는다 → 대화 메모리.
- 버튼 `UiAction`, 근거 `Citation(title, location)`.

### 4.4 바꾸는 일 — 초안과 버튼만

```python
draft = self.proposal(kind="quiz.cards_add", title="...", payload={...}, reasons=[f"사용자 요청: {req.text}"])
return AgentResult(reply=self.reply(
    "저장할까요?",
    actions=[UiAction(kind="save_proposal", label="저장", params={"index": 0})],
    proposals=[draft],
))
```

새 `kind`면 BE `Store._apply`(`notes_api/store/store.py`)에 반영 방법을 넣는다.

### 4.5 프롬프트

`agents/<Agent>/prompts/<Agent>.<용도>.v<n>.md`. 바꿀 때는 `v<n+1>`을 새로 만든다. `{이름}`은 값으로 채우고, JSON 예시의 중괄호는 `{{ }}`로 쓴다. 고정: `STUDY_NOTES_PROMPT_PINS={"notes.summary": 1}`.

구성 순서(이 저장소의 약속): 역할 → 규칙(근거 제한) → 생각하는 순서(`reasoning` 칸) → few-shot → 출력 형식 → 입력.

### 4.6 평가 질문

`src/study_notes/eval/cases/*.yaml`.

```yaml
subject_id: NB-1
screen:
  base_date: "2026-11-23"      # 선택. 기준일·보고 있는 노트
cases:
  - id: NT-008
    question: 최근에 쓴 노트 보여줘
    expected_intent: note_recent
    expected_intents: [note_recent]   # 선택. 다중 의도면 전체 목록
    must_include: ["노트"]
```

### 4.7 시험

- 규칙: `tests/unit/`에 순수 함수 시험
- 대화: `tests/graph/`에서 `build_chat_graph(InMemorySaver())`. 픽스처 `env`가 가짜 BE·가짜 모델·메모리 기록기를 끼운다.
  - 모델 답: `env.llm.reply_for("worker", "질문에 든 말", "답")`
  - ReAct: `env.llm.script("worker", [LlmResult(tool_calls=[...]), "최종 답"])`
  - 데이터 바꾸기: `env.be.notes`, `env.be.cards`, `env.be.profile`

## 5. 새 하위 Agent

1. `agents/<이름>/`에 `__init__.py`, `agent.py`, `tools.py`, `rules.py`, `prompts/`
2. `BaseAgent` 상속, `name`·`title`·`intents`
3. `agents/registry.py`의 `AGENTS`에 한 줄
4. 화면 표시 이름: `notes_ui/view.py`의 `AGENT_LABELS`
5. 체크리스트: `AGENTS.md` §7

## 6. 우리 PostgreSQL 테이블 (선택)

`STUDY_NOTES_RECORDER=postgres`면 실행 기록(모델·도구 호출, 평가)을 `AGENT_DB_SCHEMA` 스키마에 남긴다. 테이블은 `src/study_notes/db/models.py`, 변경은 Alembic(`migrations/`). Aegra 테이블은 건드리지 않는다.

```powershell
.\.venv\Scripts\python.exe -m study_notes.db migrate
```
