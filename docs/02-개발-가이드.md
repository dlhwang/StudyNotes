## 3. Aegra로 띄워 보기 (선택)

PostgreSQL 접속 정보는 `.env` 한 곳에만 적고, ai-agent와 Aegra가 같은 값을 읽는다.

1. `.env.example`을 `.env`로 복사하고 DB 항목을 채운다. `.env`는 저장소에 올리지 않는다.

| 키 | 뜻 | 예 |
|---|---|---|
| `POSTGRES_HOST` | DB 서버 IP 또는 이름 | `10.0.0.12` |
| `POSTGRES_PORT` | 포트 | `5432` |
| `POSTGRES_DB` | 데이터베이스 이름 | `aegra` |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` | 계정 | |
| `AGENT_DB_SCHEMA` | 우리 테이블(실행 기록·평가)을 둘 스키마 | `agent` |

`DATABASE_URL`은 넣지 않는다. 있으면 Aegra가 그것을 먼저 쓰고 위 값은 무시한다.

2. 서버 패키지를 넣는다.

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[server,postgres]"
```

3. 접속을 확인하고 우리 테이블을 만든다(§4.7).

```powershell
.\.venv\Scripts\python.exe -m study_notes.db check
```

```powershell
.\.venv\Scripts\python.exe -m study_notes.db migrate
```

4. Aegra를 띄운다. 처음 뜰 때 Aegra가 자기 테이블(thread·run·체크포인트)을 스스로 만든다. `aegra serve`는 이 폴더의 `.env`를 읽는다.

```powershell

```

5. 다른 터미널에서 BE처럼 붙어 본다.

```powershell

```

API 문서는 `http://127.0.0.1:2026/docs`.

## 4. 내 Agent에 기능 하나 넣기

예: 예시 Agent(`agents/tasks`)에 "내 할 일만 보여줘"를 넣는다.

### 4.1 의도

`agents/<내 Agent>/agent.py`의 `intents`에 `IntentSpec`을 추가한다. 오케스트레이터 폴더는 고치지 않는다.

```python
MY_TASKS = IntentSpec(
    "task_mine",                 # 의도 이름. 평가 질문의 expected_intent와 같은 값
    "내 할 일만 보기",            # 모델 분류에 보여 줄 설명
    (r"내할일", r"나한테온"),      # 공백을 지우고 소문자로 바꾼 질문에 거는 정규식
)

class TasksAgent(BaseAgent):
    intents = (TASK_EXPLAIN, MY_TASKS, TASK_LIST)   # 앞에 둔 것부터 규칙을 건다
```

- 규칙이 겹치면 한 질문에 여러 의도가 걸린다(최대 3개). 원하지 않으면 정규식을 좁힌다.
- 규칙에 안 걸리면 모델(역할 키 `router`)이 `help` 설명을 보고 고른다. 모델도 못 고르면 안내 답이 나간다.
- **의도 하나는 Agent 하나에만** — 시험이 확인한다.

### 4.2 업무 도구 (조회)

`agents/<내 Agent>/tools.py`

```python
class OwnerArgs(BaseModel):
    subject_id: str = Field(description="대상 ID")
    owner: str = Field(description="담당자 이름")

@agent_tool(agent="tasks", llm_selectable=True)
async def tasks_list_mine(args: OwnerArgs, ctx: ToolContext) -> list[TaskItem]:
    """담당자의 할 일만 가져온다.

    쓸 때: "내 할 일 보여줘"
    쓰지 않을 때: 전체 목록 → tasks_list_items
    """
    items = await ctx.be.list_tasks(args.subject_id, token=ctx.request.be_token)
    return [t for t in items if t.owner == args.owner]
```

- 이름은 `{Agent 이름}_{동사}_{대상}`. 틀리면 import 때 바로 오류가 난다.
- 독스트링이 없으면 오류. "언제 쓰고 언제 쓰지 않는지"를 쓴다.
- **도구는 모두 조회다.** 쓰기로 보이는 이름(`save`, `submit`, `approve` 등)이 생기면 시험이 실패한다.
- BE에 새 조회 기능이 필요하면 `tools/be_client/protocol.py`의 `BeClient`에 메서드를 넣고, `http.py`와 `tools/fakes/be.py`에 구현을 넣는다. 가짜 데이터는 합성으로만.

### 4.3 답 만들기

`agent.py`의 `run()`에서:

```python
items = await self.tool("tasks_list_mine", OwnerArgs(subject_id=self.subject_id(), owner=self.request.user.display_name))
return AgentResult(reply=self.reply(f"내 할 일 {len(items)}건입니다."))
```

- 숫자는 BE가 계산한 것을 쓴다. 모델에게 계산시키지 않는다.
- 모델로 문장을 다듬으려면 `await self.ask_llm("worker", self.prompt("용도"), req.text, 이름=값)`. 실패하면 `LlmUnavailableError`가 나니 규칙 문장으로 바꾼다. 가짜 모델은 늘 실패하므로 **규칙 문장만으로도 기능이 돌아야 한다**.
- 버튼은 `UiAction`, 근거는 `Citation`. 화면 이동·버튼 처리는 FE·BE가 한다.

### 4.4 바꾸는 일 — 초안과 버튼만 돌려준다

ai-agent는 BE에 쓰지 않는다. 바꿔야 하면 제안 초안을 답에 담고 버튼을 붙인다. 사용자가 버튼을 누르면 FE→BE가 저장·승인한다 ([01 §5](01-구조.md)).

```python
draft = self.proposal(
    kind="task.reassign",
    title="'견적서 검토' 담당을 이나래로 바꿉니다",
    payload={"task_id": "T-1", "to": "이나래"},
    reasons=[f"사용자 요청: {req.text}"],
)
return AgentResult(
    reply=self.reply(
        "이대로 바꿀까요?",
        actions=[UiAction(kind="save_proposal", label="바꾸기", params={"index": 0})],
        proposals=[draft],
    )
)
```

- `self.proposal()`이 대상 ID와 중복 방지 키(`dedupe_key`)를 붙인다. 같은 대화에서 같은 요청을 두 번 해도 키가 같다.
- 저장 말고 다른 일을 BE에 맡기려면 `UiAction(kind="backend", params={"action": "...", ...})`. `action` 이름은 BE와 맞춘다.
- 예약 그래프에서는 `rules.py`가 `ProposalDraft`를 직접 만들고 `dedupe_key`를 넣는다(예: `agents/tasks/rules.py`의 `overdue_notices`).

### 4.7 우리 테이블 추가·변경 (ORM)

우리 테이블은 SQLAlchemy ORM으로 쓰고, DDL은 Alembic이 버전으로 관리한다. **Aegra 테이블(thread·run·체크포인트 등)은 Aegra가 스스로 만들고 바꾸므로 모델도 리비전도 만들지 않는다.** `migrations/env.py`가 우리 스키마(`AGENT_DB_SCHEMA`)만 보게 걸러 둔다.

1. `src/study_notes/db/models.py`에 모델을 추가한다. 스키마는 `Base`가 자동으로 붙인다.
2. 리비전을 만든다(DB 접속 필요).

```powershell
.\.venv\Scripts\alembic.exe revision --autogenerate -m "add my_table"
```

3. `migrations/versions/`에 생긴 파일을 **꼭 읽어 본다.** 자동 생성은 이름 변경·데이터 이동을 모른다.
4. 적용한다.

```powershell
.\.venv\Scripts\python.exe -m study_notes.db migrate
```

5. 운영 DB 담당에게 줄 DDL은 DB 없이 뽑는다.

```powershell
.\.venv\Scripts\python.exe -m study_notes.db sql > ddl.sql
```

## 5. 새 하위 Agent 만들기

1. `agents/<이름>/`에 `__init__.py`, `agent.py`, `tools.py`, `rules.py`, `prompts/` (예시 `agents/tasks`를 복사해 시작해도 된다)
2. `BaseAgent`를 상속하고 `name`, `title`, `intents`를 채운다
3. `agents/registry.py`의 `AGENTS`에 한 줄 추가
4. 체크리스트: `AGENTS.md` §7

## 6. 이 틀로 새 프로젝트 시작하기

1. 복사하고 이름을 바꾼다.

```powershell
.\.venv\Scripts\python.exe tools\new_project.py D:\workspace\<프로젝트>\ai-agent <패키지_이름>
```

2. 새 폴더에서 §1을 한다(가상환경, 설치, 시험).
3. 업무에 맞게 바꾼다.

| 바꿀 곳 | 무엇을 |
|---|---|
| `core/context.py` | `subject_id`(질문이 가리키는 대상)를 업무에 맞는 이름으로 바꿀지 정한다. 예: `project_id` |
| `tools/be_client/` | `BeClient` 조회 메서드, HTTP 경로, 가짜 BE 데이터 |
| `server/auth.py` | BE와 맞춘 사용자 헤더 이름, 토큰 전달 방식 |
| `agents/` | 자기 Agent를 만들고 `registry.py`에 등록. 예시 `tasks`와 `graphs/daily_check.py`는 지운다 |
| `aegra.json` | 그래프 목록 |
| `eval/cases/` | 자기 평가 질문. `examples.yaml`은 지운다 |
| `README.md` | 프로젝트 소개, 정해진 것·안 정해진 것 |

4. 예시를 지운 뒤에도 공통 시험(`tests/unit/test_platform.py`의 쓰기 금지 시험 등)은 남긴다. 예시 도구를 쓰는 시험만 자기 도구로 바꾼다.
